# Goose-to-Sim Migration Coverage Catalog

## Audit contract

This catalog compares observable behavior in `projects/goose` with executable Sim code and the migration specifications. A matching file or type name is not implementation evidence. Tests support an assessment only when a runtime path exists. `None found` means the named Sim integration points were searched and no callable behavior was found.

Classifications are mutually exclusive:

- `C1` — already implemented in Sim and reusable without changes.
- `C2` — partially implemented in Sim and should be extended.
- `C3` — not implemented in Sim, but fully covered by an existing migration spec.
- `C4` — not implemented in Sim and only partially covered by an existing migration spec.
- `C5` — missing from the migration specs.
- `C6` — intentionally excluded; the rationale is recorded in the row.
- `C7` — internal/upstream infrastructure that does not require a direct port.

When a capability could fit more than one category, Sim implementation status takes precedence (`C1`/`C2`), then spec coverage (`C3`/`C4`/`C5`), then exclusions (`C6`/`C7`). Design references use stable design-element labels introduced in the corresponding design traceability tables.

## Decisions requiring review

1. Whether Sim should expose a standalone ACP server over stdio and/or authenticated HTTP/WebSocket.
2. Whether the invented REST/OpenAPI API remains a separate product proposal or is removed from migration scope.
3. Whether a terminal-native UI/agent CLI is a required Sim product surface, and which commands are in scope.
4. Which subscription-backed ACP/CLI providers and declarative provider presets Sim commits to support.
5. Whether in-process local inference includes MLX as well as the existing llama.cpp path, and which platforms are supported.
6. Whether persistent agent memory, Nostr sharing, Telegram gateway, arbitrary container execution, and embedded MCP Apps meet Sim's privacy/security/product goals.
7. Whether LLM-based permission judging and automatic Doctor provider switching are acceptable policies.
8. Whether Sim needs public TypeScript, Python, Kotlin, and/or Rust SDK distributions.
9. Whether UI localization is a repository-wide initiative or Goose migration work.
10. Which Goose external services (OIDC proxy, Ask AI bot) Sim will operate and support.
