# Design: CI/CD Migration Plan — Archived Workflows

## Overview

This document describes the migration architecture for reintroducing the 38 archived GitHub Actions workflows. The workflows are organized into functional groups, each with a clear migration path ranging from "copy from archive" to "full reimplementation."

### Key Architectural Decisions

| Decision | Rationale |
|----------|-----------|
| **Archive in-place within the repo** | Archived workflows remain version-controlled alongside the codebase, making restoration trivial. A subdirectory (`archive/`) is invisible to GitHub Actions. |
| **Group by priority** | Workflows are ranked by likely restoration need. High-priority workflows have the simplest migration path (often just "move from archive"). |
| **Auto-generation caveat** | Many workflows are auto-generated by `cargo xtask workflows`. The xtask code needs to be updated to exclude archived workflows, or a post-generation re-archive script must be used. |
| **No code changes to core workflows** | Archived workflows should not require changes to `run_tests.yml` or `release.yml` unless explicitly desired. |

### Correctness Properties

#### Property 1: Archive Completeness

_For any_ workflow file that was present in `.github/workflows/` before migration, that file SHALL be present in `.github/workflows/archive/` after migration OR be one of the two retained core workflows (`run_tests.yml`, `release.yml`).

**Validates: R1–R16**

#### Property 2: Core Workflow Integrity

_For any_ retained core workflow (`run_tests.yml`, `release.yml`), removing the references to archived workflows SHALL NOT change the behavior of the retained workflows for inputs that did not previously match archived workflow triggers.

**Validates: R1–R16**

#### Property 3: Restore Fidelity

_For any_ archived workflow file moved back to `.github/workflows/`, the workflow SHALL behave identically to its pre-archive version, unless the migration task explicitly modifies it.

**Validates: R1–R16**

#### Property 4: Auto-Generation Safety

_For any_ developer running `cargo xtask workflows` from the `main` branch, the archived workflow files under `.github/workflows/archive/` SHALL NOT be overwritten or duplicated into `.github/workflows/`.

**Validates: R17**

### Workflow Classification

**Group A: Direct Restore (simplest)** — Move file from `archive/` to parent directory. No code changes needed.

| Workflow | Trigger | Restore Action |
|----------|---------|----------------|
| `run_bundling.yml` | PR label | `mv archive/run_bundling.yml .` |
| `deploy_docs.yml` | `workflow_call` | `mv archive/deploy_docs.yml .` |
| `deploy_nightly_docs.yml` | Push to main | `mv archive/deploy_nightly_docs.yml .` |
| `nix_build.yml` | PR label | `mv archive/nix_build.yml .` |
| `compliance_check.yml` | Schedule | `mv archive/compliance_check.yml .` |
| `danger.yml` | PR/merge queue | `mv archive/danger.yml .` |

### Auto-Generation Considerations

Workflows with the header `# Generated from xtask::workflows::<name>` are produced by `cargo xtask workflows`. The generation source code is in `tooling/xtask/src/tasks/workflows/`. 

**Current behavior**: Running `cargo xtask workflows` regenerates ALL workflow files under `.github/workflows/`. If an auto-generated workflow is archived, running this command would recreate it in `.github/workflows/`.

**Mitigation options** (in order of preference):

1. **Preferred**: Update the xtask generation code to skip writing files that only exist in `archive/`. This could be done by checking if the file path for output should be redirected, or by maintaining an exclusion list.
2. **Fallback**: Add a `post-generation-re-archive.sh` script that moves auto-generated-but-archived workflows back to `archive/` after `cargo xtask workflows` runs.
3. **Manual**: Document that developers must re-run the archive migration script after regenerating workflows.

## Components and Interfaces

### Component 1: XTask Workflow Generator (`tooling/xtask/src/tasks/workflows/`)

**Purpose**: Generates auto-created workflow YAML files from Rust source.

**Responsibilities**:
- Defines the structure of auto-generated workflows
- Writes YAML output to `.github/workflows/`

**Required Change**: Add awareness of archived workflows so they are not regenerated into the active directory.

**Suggested Interface Change**:
```rust
// In tooling/xtask/src/tasks/workflows.rs or similar:
fn is_archived(workflow_name: &str) -> bool {
    let archived = [
        "run_bundling",
        "after_release",
        "autofix_pr",
        "deploy_collab",
        "deploy_docs",
        "deploy_nightly_docs",
        "compliance_check",
        "danger",
        "extension_tests",
        "extension_bump",
        "extension_auto_bump",
        "extension_workflow_rollout",
        "nix_build",
        "publish_extension_cli",
        "cherry_pick",
        "bump_baymax_version",
        "bump_collab_staging",
        "bump_patch_version",
        "docs_suggestions",
    ];
    archived.contains(&workflow_name)
}
```

### Component 2: Archive README (`.github/workflows/archive/README.md`)

**Purpose**: Documents the archive structure and migration procedure.

**Responsibilities**:
- Lists all archived workflows with descriptions
- Provides migration steps for restoration
- Documents the `cargo xtask workflows` caveat

### Component 3: Post-Archive Audit Script (optional)

**Purpose**: Verifies that no workflow references are broken after archiving.

**Suggested implementation**: A simple grep to check that no remaining workflow references an archived file path.

## Error Handling

| Failure Mode | Impact | Mitigation |
|--------------|--------|------------|
| `cargo xtask workflows` regenerates archived workflows to active directory | Archived workflows become active again | Update xtask code or add re-archive script; add CI check |
| Archived workflow references another archived workflow (e.g., `after_release.yml` → `deploy_docs.yml`) | Stale reference in archive, no functional impact | Document cross-references in README; restore as a group |
| Developer forgets to re-add `extension_tests` job to `run_tests.yml` when restoring extension CI | Extension tests won't run | Document in README; consider adding a shared composite action |

## Testing Strategy

- **Unit Test**: Verify xtask exclusion list matches archived auto-generated files
- **Integration Test**: Restore a Group A workflow (e.g., `danger.yml`), trigger it, verify it runs
- **Regression Test**: Run `run_tests.yml` after archive to verify no broken references
- **Manual Test**: Run `cargo xtask workflows` and verify archived files are not regenerated to active directory
